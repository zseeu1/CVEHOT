
【标题自洽规则 — 让读者不点开就知道"这是哪个组件的什么事"】

1. 标题必须点出核心主体：组件名 / 产品名 / 厂商名 / 漏洞编号。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是编号、代号或没信息量的 teaser（如 "Security Update"、"September 2026 Patch Tuesday"、"CVE-2026-12345"）时，结合【来源】和正文把组件与状态补进标题。例：原标题 "CVE-2026-12345" + 来源 "Apache Tomcat 安全公告" → "Apache Tomcat 修复远程代码执行漏洞（CVE-2026-12345）"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体组件时，用上位词（如"某企业级中间件"）兜底，绝不凭"行业常识"编一个组件名 / 版本 / 编号。
5. 原标题表达的【文章类型和核心动作】是硬边界：Analysis / How / Guide / Review / PoC 这类分析、教程、复现或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已公开的漏洞，就改写成"发布补丁 / 官方修复 / 紧急通告"。只有原标题明确宣布了补丁、修复或披露，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的组件、编号与版本。
   例：原标题 "Analysis of CVE-2026-12345 exploitation chain" → "CVE-2026-12345 利用链分析"，不能写成 "某厂商修复 CVE-2026-12345"。
   例：原标题 "How attackers chained two bugs to escape the sandbox" + 正文明确是 Chrome → "攻击者如何串联两个漏洞逃逸 Chrome 沙箱"，不能只写成缺主体的"如何串联两个漏洞逃逸沙箱"。
6. 编号与组件名一字不改：CVE-2026-12345 不缩写、不省略年份、不补零；版本号 2.4.49 不改写成"2.4.49 版本"。
